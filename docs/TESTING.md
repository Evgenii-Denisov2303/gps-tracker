# Проверки

## Backend

Из `backend`, Python 3.10+:

```sh
python -m venv .venv
# Linux: source .venv/bin/activate
# Windows: .venv\Scripts\Activate.ps1
pip install -r requirements-dev.txt
pytest -q
```

Обычные тесты используют изолированную SQLite в памяти и не трогают рабочую БД.
Для PostgreSQL передайте `TEST_DATABASE_URL` **только отдельной одноразовой БД**:
фикстура создаёт и удаляет таблицы. Никогда не передавайте URL рабочей `tracker`.

Из корня проекта полностью изолированный прогон PostgreSQL и миграций:

```sh
docker compose -f compose.test.yml up --build --abort-on-container-exit --exit-code-from tests
docker compose -f compose.test.yml down
```

Используются отдельная Docker-сеть и временная БД в tmpfs без внешнего порта.
Рабочий `gps-tracker` не останавливается и не изменяется.
Список проверок: закрытые методы, CSRF, logout, лимит входа, привязка токена к машине,
отзыв, валидация времени/размера, дубли, очередь не по порядку, старая загрузка не «онлайн»,
часовой пояс, GPS-дребезг, невозможные скачки, короткие стоянки, разрывы, полночь, смена трекера.

## Миграции

На отдельной БД: `alembic upgrade head`, `alembic current`, `alembic check`.
При изменении модели создавайте новую миграцию; `0001` не меняйте после первого развёртывания.

## Симулятор

1. В локальном кабинете создайте автомобиль **«ДЕМО — синтетический маршрут»**.
2. Создайте для него устройство «Симулятор» и скопируйте токен.
3. Из корня: `python tools/simulate.py --url http://localhost:8080`.
4. Введите токен в скрытом запросе. Будет отправлено 136 вымышленных точек
   за последние 45 минут, с двумя остановками. Это не настоящая поездка.
5. В кабинете нажмите «Сегодня» и «Маршрут за день».

Не запускайте симулятор с токеном реальной машины, чтобы не смешивать историю.

## Браузер и телефон

Логика свежести GPS, связи, батареи и ответа сайта: `node --test web/tracker-status.test.cjs`
из корня (Node.js 22+). Тесты используют вымышленные данные и не обращаются к серверу.

Проверить вход, неверный пароль, пустое состояние, создание машины/трекера,
карту, маршрут, остановки, смену даты, возврат к текущей точке, отзыв, выход и повторный вход.
Размеры: 320/360/390/760/768/980/1024/1440 px, соседние точки брейкпоинтов,
телефон в landscape, квадратный, высокий и короткий desktop viewport.
Сравнить scrollWidth/clientWidth и фактический размер карты; проверить, что кнопки доступны.
При обрыве API старые значения не должны продолжать выглядеть свежими.
Проверить heartbeat без GPS: телефон на связи, скорость скрыта, показаны свежая батарея
и состояние разрешений. Отдельно проверить старый клиент без heartbeat и устаревание диагностики.

Android: `gradle testDebugUnitTest lintDebug assembleDebug`, затем обязательные
[натурные проверки](INSTALL_ANDROID.md). Unit-тесты не проверяют OEM-ограничения,
реальный GPS, отключённый экран, SIM и автоматический запуск на конкретном устройстве.

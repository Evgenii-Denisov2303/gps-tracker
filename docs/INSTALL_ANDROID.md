# Настройка телефона

1. Найдите Android 8.0+ с рабочим GPS, SIM и мобильным интернетом. Проверьте автоматические дату/время.
2. Скачайте [готовый APK](DOWNLOAD.md) или установите собственную сборку
   из `artifacts/android` / `android/app/build/outputs/apk/debug`.
   На телефоне подтвердите установку из выбранного источника самостоятельно.
3. Введите HTTPS-адрес сервера и токен из кабинета. Нажмите «Сохранить настройки».
   Токен владельца/пароль сюда не подходят. Не передавайте токен посторонним.
4. Кнопкой «Разрешить точную геолокацию» разрешите точное местоположение.
5. В настройках приложения → «Разрешения» → «Местоположение» → **«Разрешать всегда»**.
   На Android 8–9 отдельного режима «Всегда» нет, достаточно геолокации.
   На Android 10 приложение запрашивает фон отдельно; Android 11+ выдаёт его через системные настройки.
6. Включите системную геолокацию. На Android 13+ разрешите уведомления.
7. Через настройки батареи уберите оптимизацию для приложения, разрешите работу в фоне.
   На Xiaomi/Huawei/Oppo и других оболочках проверьте также автозапуск и ограничения фоновой активности.
8. Нажмите «Запустить трекер». Должно появиться постоянное уведомление.
9. Выйдите на улицу, дождитесь свежей GPS-точки и успешной отправки. Владелец проверяет карту сайта.
10. Установите телефон в машине с надёжной зарядкой и приёмом спутников.

Телефон не показывает административную карту. Если экран погас, сбор продолжается через foreground service.
Интервал движения около 20 секунд, после пяти минут на месте — 120 секунд.
GPS-приёмник остаётся активным. Уведомление нельзя скрывать: это штатный прозрачный мониторинг.

## Обновление 1.0.1 и время GPS

На Pixel с Android 11 обнаружена неверная календарная дата внутри GPS-измерения,
хотя системные часы телефона показывали правильную дату. Начиная с 1.0.1 время новой
точки берётся из часов телефона за вычетом возраста измерения по монотонным часам
Android (`Location.getElapsedRealtimeNanos`). Точки старше двух минут и измерения
с временем из будущего по монотонным часам отбрасываются. При отправке после отсутствия
интернета сохранённое время не меняется. Автоматические дата/время телефона должны быть включены.
Ранее отправленная история не переписывается.

Обновление устанавливайте поверх предыдущей версии, без удаления приложения и очистки
данных. Затем откройте трекер и нажмите «Запустить трекер»: Android может остановить
службу при обновлении. Проверьте на сайте время новой точки и ещё одну отправку после
выключения экрана. Токен и настройки сохраняются при совпадающей подписи APK.

Для обновления тестовой сборки используйте исходный ключ подписи; случайный новый
debug-ключ не позволит установить APK поверх предыдущего. Ключ хранится вне проекта,
не включается в Git или архив исходников. Пример PowerShell с вашим ключом:

```powershell
$env:ANDROID_SIGNING_KEY = "C:\keys\tracker-debug.keystore"
docker build -f android/Dockerfile --secret "id=android_debug_keystore,src=$env:ANDROID_SIGNING_KEY" --output "type=local,dest=artifacts/android" android
```

Без указанного секрета Docker создаёт отдельную тестовую подпись; такая сборка не
предназначена для обновления уже установленных экземпляров. Для промышленного выпуска
нужны отдельный release-ключ и его резервная копия. Ключ текущей тестовой сборки сохранён
отдельно; builder-образы содержат тестовый ключ и не должны публиковаться.

## Очередь и замена токена

Точки сохраняются до отправки в SQLite. Подтверждённые сервером UUID удаляются из очереди.
Таймаут после фактически успешной отправки безопасен: повтор не создаст дублей.
При восстановлении сети свежая точка отправляется вместе со старейшими точками очереди,
поэтому карта не ждёт выгрузки всей истории. Повтор при ошибке — с задержкой до пяти минут.

Токен хранится с AES-GCM / Android Keystore, резервное копирование приложения отключено.
HTTPS обязателен, редиректы при отправке запрещены, проверка TLS не отключается.
При смене сервера/токена с непустой очередью приложение просит сначала передать старые точки:
это исключает запись старой истории на другую машину. Если старый токен отозван и передача невозможна,
можно отдельно подтвердить очистку очереди на телефоне; данные будут потеряны.

## Автозапуск

После обычной перезагрузки приложение получает BOOT_COMPLETED и запускает GPS-service,
если мониторинг был включён и разрешена фоновая геолокация.
Первое разблокирование после загрузки необходимо: приложение не работает в Direct Boot.
Если Android запретит старт, появится уведомление с предложением открыть трекер.
После системной «Принудительной остановки» автоматического восстановления до ручного открытия нет.
Не обещайте круглосуточную надёжность до проверки конкретной модели телефона.

## Приёмочные испытания на реальном телефоне

- 30–60 минут поездки с выключенным экраном: точки поступают, скорость/батарея правдоподобны.
- Стоянка 10 минут: одна остановка, GPS-дребезг не добавляет заметного пробега.
- Отключить мобильный интернет на 10 минут: очередь растёт, сайт показывает устаревание.
- Включить интернет: очередь уменьшается, история восстанавливается, дубли не появляются.
- Обычная перезагрузка, затем разблокирование: мониторинг возобновляется.
- Отключить зарядку: сайт после следующей точки показывает работу от батареи.
- Отключить GPS: на телефоне видно ошибку, сайт не показывает старую скорость как текущую.
- Отозвать токен: сервер отвечает 401, телефон сохраняет очередь и сообщает об ошибке.
- Ночь на стоянке: утром телефон работает, очередь и время последней отправки понятны.

Без проверки на вашем телефоне эти испытания не считаются пройденными.
SIM с интернетом оплачивается отдельно; 1–3 ГБ — исходный ориентир из ТЗ, а не измеренный расход.
Контролируйте фактический трафик, температуру и состояние батареи старого телефона.

# API v1

Все даты ISO 8601 с явным часовым поясом. База хранит UTC.
Скорость **км/ч**, точность/радиус **метры**, направление **градусы [0, 360)**,
заряд **целое 0..100**, длительность **секунды**.
Android переводит стандартную скорость GPS из м/с в км/ч до отправки.

## Авторизация владельца

`POST /api/v1/auth/login` — JSON `{"username":"owner","password":"…"}`.
Обязателен заголовок `Origin`, совпадающий с `PUBLIC_ORIGIN`.
Ответ выдаёт HttpOnly cookie `gps_session` и JSON с `csrf_token`, `username`, `timezone`.
Cookie в production имеет Secure и SameSite=Strict. Срок — 12 часов.

`GET /api/v1/auth/me` — данные сессии и CSRF.
`POST /api/v1/auth/logout` — отзывает сессию, ответ 204.
Для POST/DELETE владельца нужны cookie, `Origin` и `X-CSRF-Token`.
Нет публичной регистрации владельцев: только CLI администратора VPS.

## Автомобили и устройства

Все методы этого раздела требуют сессии владельца.

| Метод | Путь | Данные / результат |
|---|---|---|
| GET | `/api/v1/vehicles` | Список машин |
| POST | `/api/v1/vehicles` | `{ "name": "Газель №1", "plate": "", "description": "" }`, 201 |
| GET | `/api/v1/vehicles/{id}/devices` | Устройства без хэшей и токенов |
| POST | `/api/v1/vehicles/{id}/devices` | `{ "name": "Телефон" }` → `{ "id": 1, "token": "…" }`, 201 |
| DELETE | `/api/v1/devices/{id}` | Отзыв токена, 204; история остаётся |
| GET | `/api/v1/vehicles/{id}/latest` | Последняя точка приемлемой точности, свежесть, последний контакт |
| GET | `/api/v1/vehicles/{id}/route?date=YYYY-MM-DD` | segments, stops, summary, timezone |
| GET | `/api/v1/vehicles/{id}/stops?date=YYYY-MM-DD` | Остановки за день |

## Приём GPS

`POST /api/v1/locations`

```http
Authorization: Bearer DEVICE_TOKEN
Content-Type: application/json
```

```json
{
  "points": [
    {
      "event_id": "fa65bb05-8151-42a7-9d8c-69bc184493a4",
      "latitude": 55.7901,
      "longitude": 49.1204,
      "gps_timestamp": "2026-10-03T10:20:00Z",
      "speed": 46.0,
      "accuracy": 8.0,
      "heading": 120.0,
      "battery_level": 82,
      "charging": true
    }
  ]
}
```

Обязательны UUID `event_id`, широта, долгота, timestamp с зоной и положительная accuracy.
Остальные поля могут отсутствовать/null. ID устройства и машины сервер берёт из токена.
Произвольные дополнительные поля запрещены. Пакет 1..500 точек, тело до 512 КиБ.
Координаты вне диапазона, NaN/Infinity, даты без зоны/раньше 2020 и более чем на 2 минуты
в будущем отклоняются. Пакет с невалидной точкой целиком получает 422 без частичного сохранения.

Ответ 200:

```json
{"accepted": 1, "acknowledged": ["fa65bb05-8151-42a7-9d8c-69bc184493a4"], "server_time": "2026-10-03T10:20:01Z"}
```

`accepted` — новые записи, `acknowledged` — все уже сохранённые/повторные UUID пакета.
Повтор с тем же `(device_id, event_id)` не перезаписывает данные и не создаёт дубль.
Удаляйте из локальной очереди только подтверждённые UUID после 200; при таймауте повторите
с прежними UUID. При 401 проверьте/замените токен, при 422 проверьте часы и JSON.
Нет ограничения «старше суток»: очередь после длительного офлайна тоже принимается.
Дата приёма обновляет last_contact, но свежесть карты считается по gps_timestamp.

`latest.status`: `fresh`, `stale`, `offline`. `age_seconds: null` означает отсутствие точки.
Устаревшая точка может оставаться на карте с её реальным временем, но не выдаётся за текущую скорость.
`last_contact` — дата последнего принятого пакета или сигнала связи активного устройства;
это не дата GPS. `contact_age_seconds` и `connection_status` отражают именно связь.
`device_health` — последний снимок диагностики этого устройства либо `null` для старого клиента.
В нём есть поля из запроса heartbeat ниже, серверные `received_at` и `age_seconds`.
Снимок старше `stale_seconds` нельзя показывать как актуальный, даже если позже пришёл пакет точек.

`route.segments` — массив независимых линий. Нельзя соединять их через промежутки без данных.
`summary` содержит distance_km, first_point, last_point, max_speed_kmh, moving_seconds,
stopped_seconds, unknown_seconds, stop_count, point_count, filtered_points.
`stops.ongoing` означает, что наблюдение закончилось на этой остановке,
а не доказательство того, что автомобиль всё ещё стоит там сейчас.

`GET /api/v1/health` публичный, проверяет доступность БД; координат не содержит.
Коды ошибок: 401 — вход/токен, 403 — Origin/CSRF, 404 — объект, 413 — размер,
422 — данные, 429 — лимит входа. Публичный Swagger отключён.

## Сигнал связи устройства (1.0.2+)

`POST /api/v1/heartbeat` — тот же `Authorization: Bearer DEVICE_TOKEN`.
Сессия владельца или зрителя вместо токена не подходит.

```json
{
  "app_version": "1.0.2",
  "battery_level": 82,
  "charging": true,
  "gps_enabled": true,
  "location_permission": true,
  "background_permission": true,
  "battery_optimization_exempt": true,
  "gps_age_seconds": 12,
  "queue_count": 0
}
```

Заряд и состояние зарядки допускают `null`/отсутствие; возраст GPS — `null`, если после
запуска ещё не было принятого измерения. Остальные поля обязательны. Счётчики неотрицательные,
не более 2147483647; версия — 1..32 символа `[0-9A-Za-z.+-]`. Лишние поля запрещены.
Устройство и автомобиль определяет токен. Отозванный токен не принимается.
Ответ 200: `{"server_time":"2026-10-04T12:00:00Z"}`.

Сервер сохраняет только последний снимок и собственное время получения. Heartbeat
не создаёт точек, не меняет маршрут, пробег или время GPS. Клиент не ставит такие запросы
в офлайн-очередь: после восстановления сети отправляет свежее состояние.

# Доступ только для просмотра

Ответы `/api/v1/auth/login` и `/api/v1/auth/me` содержат `role`: `owner` или `viewer`.
Роль берётся из базы, клиент не может выбрать её при входе.
Зритель может читать список автомобилей, текущую позицию, маршруты и остановки всех автомобилей системы.
Управление автомобилями и токенами, включая список устройств, доступно только владельцу;
для зрителя эти запросы возвращают 403 даже с действующей сессией и CSRF-токеном.
Учётная запись зрителя не даёт права отправлять координаты: для этого нужен токен устройства.
Вход, выход, защита сессии и ограничение попыток входа одинаковы для обеих ролей.


## Автомобильный Navtelecom (экспериментальный приёмник)

`POST /api/v1/vehicles/{id}/hardware-devices` — только владелец, с CSRF.
Тело: `{"name":"START S-4011","imei":"15 цифр с прибора"}`.
Ответ 201: id/kind/imei, без токена Android. Повторный IMEI — 409.
Общий `DELETE /api/v1/devices/{id}` отзывает приём данных на следующем пакете.
Список устройств содержит `kind` и `imei` только для владельца.
`latest` содержит `device_kind`, аппаратную `device_health` с navigation_valid,
satellites, main_voltage/backup_voltage. `point.accuracy` может быть null:
прибор не сообщает метрическую точность. Android API по-прежнему требует accuracy.
Подробности транспорта и обязательные ограничения: [INSTALL_NAVTELECOM.md](INSTALL_NAVTELECOM.md).


### Сохранение входа

`POST /api/v1/auth/login` принимает необязательный boolean `remember_me` (по умолчанию `false`).
При `true` HttpOnly/Secure/SameSite=Strict cookie и серверная сессия действуют 30 дней без продления.
При `false` cookie сессионная, серверный срок — `SESSION_HOURS` (по умолчанию 12 часов).
Восстановление вкладок браузером может сохранять сессионные cookie; «Выйти» отзывает сессию на сервере в обоих режимах.
Пароль не сохраняется в localStorage. Права owner/viewer и проверка CSRF сохраняются.

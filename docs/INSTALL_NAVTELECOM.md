# START S-4011: подготовка и подключение

Статус: реализован и проверяется программно приёмник **базового FLEX 1.0**.
Реальный START S-4011 ещё не подключался. Совместимость конкретной прошивки,
профиля записи и защищённого подключения необходимо проверить на приборе.
Это не утверждение о завершённой приёмке оборудования.

## Что уже реализовано

- NTCB: handshake IMEI, согласование FLEX, проверка XOR заголовка и данных.
- FLEX: архив `~A`, внеочередные события `~T`, состояние `~C`, CRC8, ping.
- TCP: произвольное разделение и объединение пакетов, тайм-ауты, ограничение
  размера и одновременных соединений. UDP не поддерживается.
- Регистрация владельцем, запрет неизвестных/отключённых IMEI, повторная проверка
  доступа при каждом пакете. Зритель не может регистрировать устройства.
- Точки и исходные поля событий сохраняются одной транзакцией до подтверждения.
  Повторная выгрузка архива не дублирует точки. Невалидная навигация сохраняется
  для диагностики, но не превращается в позицию автомобиля.
- Общие карта, история, остановки и фильтрация скачков. Напряжение основного и
  резервного питания, спутники, состояние навигации. Точность в метрах не выдумывается.

## Ограничение перед подключением через SIM

**Этот приёмник пока принимает только незашифрованный FLEX в доверенной сети.**
IMEI — идентификатор, а не секрет. CRC обнаруживает повреждение, но не подделку.
HTTPS сайта не защищает отдельное TCP-соединение прибора. Нативный AES-контейнер
Navtelecom (`*>CODE`, `#`) здесь не реализован и будет отклонён без подтверждения.

`compose.flex.yml` публикует порт **только на 127.0.0.1:5221**. Не заменяйте этот
адрес на `0.0.0.0` для обычной SIM. Для эксплуатации нужны либо закрытый APN с
защищённым маршрутом до VPS, либо отдельная реализация/проверка нативного
шифрования на конкретном приборе. Закрытый APN может требовать услуг оператора;
он не включён в проект. VPN на VPS сам по себе не подключает к нему трекер.

Перед заказом или настройкой уточните у продавца:

1. Точная модификация S-4011 и поддерживаемые сотовые диапазоны для вашего региона.
2. Доступ к NTC Configurator, отсутствие блокировки на сервер продавца.
3. Поддержка FLEX с выбором передаваемых полей и согласованием версии 1.0.
4. Поддержка AES именно этой прошивкой, актуальная спецификация и пример
   зашифрованного обмена с сервером. Не передавайте ключи в публичный репозиторий.

Документация v6 описывает AES-CBC, но её текст не заменяет проверку реального
обмена. До решения этого пункта **обычная SIM → публичный VPS не готова к запуску**.

## Запуск подготовленного приёмника

Из корня проекта с настроенным `.env`:

```sh
docker compose -f docker-compose.yml -f compose.production.yml -f compose.flex.yml up -d --build
docker compose -f docker-compose.yml -f compose.production.yml -f compose.flex.yml logs --tail=50 flex
```

Для локального стенда замените `compose.production.yml` на `compose.local.yml`.
Сначала API выполняет миграцию 0004, затем запускается приёмник. PostgreSQL и
приёмник не становятся публично доступны. Дополнительно можно задать список
доверенных CIDR через `FLEX_ALLOWED_NETWORKS`; это не заменяет защиту канала.

Владелец сайта открывает «Устройства» → «Автомобильный START S-4011», вводит
название и 15 цифр IMEI с наклейки. Не создавайте вымышленные IMEI в рабочей машине.
Регистрировать и отзывать доступ может только владелец. Повторная регистрация
отозванного IMEI запрещена: его восстановление требует осознанного действия
администратора базы. Секретный токен Android для аппаратного трекера не используется.

## Профиль NTC Configurator для стендовой проверки

Подключите прибор по USB и сохраните исходную конфигурацию. Названия полей могут
отличаться между прошивками; точные значения сверяйте в конфигураторе устройства.

| Параметр | Значение |
|---|---|
| Сервер | Адрес приёмника, достижимый через согласованный защищённый канал |
| Порт | TCP 5221 |
| Протокол | FLEX; сервер согласует базовую версию 1.0 |
| Объект / диспетчерский центр | Обычно 0 / 1; ответы меняют ID местами |
| Поля | Только перечисленные ниже; остальные выключить |
| Запись при движении | Для начала каждые 5 секунд |
| Стоянка | Каждые 30 секунд |
| Выгрузка | Архив, внеочередные сообщения и текущее состояние включены |
| Поддержание TCP | Чаще 90 секунд, например каждые 30 секунд |

Поддерживаются поля 1–20 структуры FLEX. Рекомендуемый набор:

| Номера | Данные |
|---|---|
| 1, 2, 3 | Номер записи, событие, время события |
| 4, 5, 7 | Статус устройства, модулей, GSM |
| 8, 9, 10, 11 | Валидность/спутники, время GPS, широта, долгота |
| 13, 14 | Скорость и курс |
| 19, 20 | Основное и резервное напряжение |

В конфигураторе могут быть обязательные поля; они должны укладываться в 1–20.
При неподдерживаемой маске соединение закрывается, данные не подтверждаются.
Сервер не угадывает формат дополнительных датчиков, не принимает CAN, фото,
расширенные `~E/~X`, команды управления и новые поля FLEX 2/3.

Для SIM нужны мобильные данные и APN оператора. PIN и настройку питания проверяйте
по паспорту конкретной модификации; подключение к электрике автомобиля поручите
установщику. На прибор APK не устанавливается.

## Проверка на приборе после получения

1. Зарегистрировать настоящий IMEI и проверить защищённое соединение отдельно.
2. На открытом месте дождаться валидной навигации и позиции на сайте.
3. Проверить время, скорость, направление, напряжение и число спутников.
4. Сделать короткую поездку: точки появляются в истории выбранного дня.
5. На время отключить передачу данных и вернуть связь: архив должен догрузиться
   без дублей; старая точка не должна выглядеть как свежая.
6. Проверить отключение/восстановление внешнего питания и перезапуск устройства.
7. После успешной проверки отключить Android-трекер, затем отозвать его токен.
   Одновременные источники для одной машины могут переключать текущую позицию.

Рабочие координаты не следует использовать для публичного демонстрационного теста.
Сырые записи `hardware_records` — такая же приватная история; они входят в резервную
копию БД. Автоматическое удаление старой истории пока не настроено.

## Источники и границы проверки

- [Протокол производителя, v6](https://downloads.navtelecom.ru/documentation/protocol/protocol_of_information_exchange_navtelecom_v6.0_%28120418%29.pdf):
  NTCB/FLEX, таблица полей, контрольные суммы; независимый тестовый пакет — с.118–119.
- [NTC Configurator](https://wiki.navtelecom.ru/doc/manual/ru_operations_manual_ntc_configurator_v3.pdf).
- [Настройка AES у производителя](https://wiki.navtelecom.ru/misc/ru_article_config_encryption_aes.pdf).

Автотесты: `backend/tests/test_flex.py`, `web/tracker-status.test.cjs`.
Сокетные тесты эмулируют отправителя; официальный эмулятор производителя и живой
S-4011 ими не заменяются. Новый Android APK для этой интеграции не нужен.

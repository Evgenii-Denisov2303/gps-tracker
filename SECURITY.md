# Безопасность и приватность

Код и установщик не предоставляют доступа к рабочему серверу владельца проекта.
Каждая установка использует свои пароли, токены, домен и базу данных.

- Для телефона нужен токен устройства; для карты — отдельный аккаунт.
- Роль `viewer` читает историю всех автомобилей этой установки, но не управляет ими.
- Не размещайте API через HTTP в интернете. Для Android необходим действительный HTTPS.
- Не добавляйте `.env`, ключи подписи, дампы БД, токены и служебные записи в Git.
- Не публикуйте реальные координаты, маршруты сотрудников и секреты в Issues или скриншотах.
- Локальный режим `compose.local.yml` предназначен для разработки на собственном компьютере.
- APK 1.0.1 — тестовый, с debug-подписью. Для промышленного выпуска требуется собственная
  release-подпись и отдельное хранение ключа. APK не содержит встроенных данных доступа.
- Перед использованием уведомите сотрудников и определите правила доступа и хранения истории.

При обнаружении уязвимости не публикуйте рабочие токены и подробности её эксплуатации
в общедоступном обсуждении. Если на GitHub доступна кнопка **Security → Report a vulnerability**,
используйте её для приватного сообщения. Обычные ошибки интерфейса можно описывать в Issues
на синтетических данных.

Это MVP без независимого аудита безопасности. Проверенные сценарии и ограничения
перечислены в [статусе проверки](docs/STATUS.md).
